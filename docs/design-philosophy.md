# Cursor共有用｜競馬診断→漫画→商品紹介ファネルの設計思想

> このドキュメントは、今後の設計・コード・DB・UIの判断基準です。
> 「売るための診断ページ」ではなく、「自分に合った馬券との付き合い方を見つける診断」を作ります。

## 0. 今回やりたいこと

単純な「競馬商品を売るLP」ではない。

**中心フロー:**

```
YouTube → LINE → 馬券診断 → 診断結果 → 漫画・無料コンテンツ・商品紹介
```

**最終目的は「全員に有料商品を売る」ではない。**

診断を通じて、その人自身に以下を理解してもらい、**その人に合った次の行動**を提示する:

- 自分が馬券に何を求めているのか
- 何に困っているのか
- どこまで他人に任せたいのか

**分岐させたい出口:**

| 出口 | 内容 |
|------|------|
| A | 無料コンテンツだけで十分な人 |
| B | 無料サービスを使った方がいい人 |
| C | 無料登録型アフィリエイト案件が合う人 |
| D | 有料商品が合う人 |
| E | 今は何も買わない方がいい人 |
| F | 将来的に有料商品を検討する可能性がある人 |

→ **「売るための診断」ではなく、「適切な出口を選ぶための診断」**

---

## 1. 一番重要な思想

❌ 商品 → 欲しくさせる

✅ 問題の自覚 → 欲しい機能の自覚 → 条件の整理 → その条件を満たす商品・サービスとの出会い

ユーザー自身が診断や漫画を進めながら:

1. 自分の馬券スタイルを理解する
2. 自分の悩みに気づく
3. なぜ今までうまくいかなかったのか理解する
4. 自分が欲しい解決方法の条件を理解する
5. その条件に合う選択肢を知る

---

## 2. 「サブリミナル的な仕掛け」の本当の意味

心理操作ではない。**ユーザー自身が自分の問題と欲求を言語化できるようにすること。**

例: 「馬連3点の商品があります。買いませんか？」→ 弱い

代わりに質問の連鎖:

```
本命馬を考えること自体は楽しいですか？ → YES
最後の相手選びで買い目が増えることがありますか？ → YES
全部予想してもらうより、自分の予想を残したまま最後の判断材料だけ欲しいですか？ → YES
```

→ 本人の中に自己認識が生まれる → 「あなたはセカンドオピニオン型です」

---

## 3. 診断質問の「表の目的」と「裏の目的」

| 表向き | 内部的 |
|--------|--------|
| 馬券タイプ・性格・好みを診断 | 悩みの発見、欲求の発見、有料/無料適性、各種スコアリング |

**内部スコアリング軸:** 自力/他力、時短、高配当/的中率、少点数、資金管理、連敗耐性、月額抵抗 等

---

## 4–6. 質問設計の原則

- 「自分の問題はこれだ」と本人に認識してもらう質問にする
- 「理想」を本人に選ばせる（何を欲しいと思っているかを明確化）
- 小さな自己認識を積み重ね、最後に本人の回答を引用して結果を返す

---

## 7–8. 漫画と商品の役割

**漫画:** 診断で言語化した悩みを物語として疑似体験させる。商品を出さない段階で「自分が欲しかったものはこれかも」と気づかせる。

**商品:** 「答え合わせ」として登場。必要条件を本人と一緒に定義してから、条件に近い選択肢の一つとして提示。

---

## 9–14. 複数出口の設計

| 出口 | 診断結果例 | 運営者利益 |
|------|-----------|-----------|
| A: 無料で十分 | 有料サービスは不要 | 0円（信用構築） |
| B: 無料+アフィ | 無料登録案件 | 成果報酬 |
| C: 有料適合 | タイプ別有料商品 | 成果報酬 |
| D: 今は不要 | 何も売らない | LINE継続 |

**Pull型:** ユーザーから「もっと知りたい」「有料版は？」と聞かれたときに初めて商品を提示。

---

## 15–16. 運営者側の「商品カルテ」

ユーザーから見えるのは診断・無料情報・必要に応じた商品のみ。

裏側では **悩み×タイプ → 第一候補 / 第二候補 / 収益** のマッピングを管理。

---

## 17–18. 商品開拓と収益

❌ 報酬額順の商品開拓

✅ 診断結果の「空席」を埋める商品開拓

**収益方法:** ①収益なし無料 ②無料成果報酬 ③有料成果報酬 ④自社商品 ⑤LINE残留

**優先順位:** 1.ユーザーに合う 2.信頼を損なわない 3.継続利用 4.収益化

---

## 19–22. 信頼構築の原則

- 「利益0円の出口」を意図的に残す
- 診断結果は商品名にしない（「うま連破壊神タイプ」❌ → 「自力予想×少点数セカンドオピニオン型」✅）
- 有料商品の「向かない人」も明記する

---

## 20. 独自診断軸

| 軸 | 左 ← → 右 |
|----|-----------|
| 自力/他力 | 自分で予想 ← → 任せたい |
| 安定/破壊力 | 的中率 ← → 高配当 |
| 少点数/広く | 絞る ← → 機会を広げる |
| データ/直感 | 数字 ← → 感覚 |
| 短時間/研究型 | 効率 ← → 予想を楽しむ |
| 冷静/感情影響型 | 安定判断 ← → 連敗等で変わる |

---

## 23–26. ファネル全体像

```
YouTube → LINE登録 → 馬券タイプ診断 → タイプ判定 → タイプ別漫画
  → 「必要な3条件」提示 → 分岐（無料 / 無料案件 / 有料 / 今は不要）
```

CTAも段階別: 無料で続き → 攻略法 → 選択肢 → 比較 → 詳細

---

## 27. ポジション

「競馬商品を売っている人」ではなく、**「自分に合った馬券スタイル・サービスを診断してくれる場所」**

---

## 35. 絶対に避けたいこと

1. 全員同じ商品
2. 露骨な購入審査質問
3. 診断結果＝商品名
4. 漫画がただの商品広告
5. 不安だけ煽る
6. 必ず勝てるように見せる
7. 無料と言いながら実質有料誘導だけ
8. アフィリエイトを隠す
9. 報酬だけで商品を優先

---

## 36–37. 本質

**「自分を理解する診断」** → その結果として適切なサービスを提示

ユーザーに感じてもらいたい: 「売られた」ではなく **「自分で選んだ」「自分のことが少し分かった」**

---

## 39. 現段階の大きな仮説

最も相性が良さそうな層: **「自分で予想したいが最後の判断材料が欲しい人」** へのセカンドオピニオン訴求

→ ただし診断結果の一つに留める（全員をここに送らない）

---

## 40. Cursorへの依頼（実装優先順位）

設計・コード・DB・UIでは常に以下を優先:

1. ユーザーの自己理解
2. 悩みの分類
3. タイプ判定
4. 無料を含めた複数出口
5. 商品適合判定
6. 漫画分岐
7. CTA分岐
8. 行動計測
9. 後から商品を追加できる構造
10. 特定商品に依存しない設計

**診断ロジックと商品を直接ベタ結合しない。**

```
回答 → 特性スコア → 診断タイプ → ニーズ・悩みタグ → 適合条件
  → 候補コンテンツ/候補商品 → 優先順位付け → 表示
```

---

## 最終コンセプト

> 競馬商品を売る診断ではなく、その人に合う「馬券との付き合い方」を見つける診断を作る。
> 「今のあなたには何も買わなくていい」という回答も、本当に存在させる。
> 診断そのものを、商品開拓・漫画・LINE・YouTube・アフィリエイトを束ねる中心装置にする。
