# アーキテクチャ設計

## 核心原則

**診断ロジックと商品を直接ベタ結合しない。**

すべての出力は、以下のパイプラインを経由する:

```
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌──────────────┐
│  回答   │ →  │ 特性スコア   │ →  │  診断タイプ  │ →  │ ニーズ/悩み  │
└─────────┘    └─────────────┘    └─────────────┘    │    タグ       │
                                                       └──────┬───────┘
                                                              ↓
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌──────────────┐
│  表示   │ ←  │ 優先順位付け │ ←  │ 候補商品/   │ ←  │  適合条件    │
└─────────┘    └─────────────┘    │ コンテンツ   │    └──────────────┘
                                    └─────────────┘
```

## レイヤー構成

### Layer 1: 回答収集（Presentation）

- 診断UI（質問表示・選択肢・進捗）
- 漫画ビューア
- CTAボタン群

**責務:** ユーザー入力の収集と表示のみ。商品判定ロジックを持たない。

### Layer 2: スコアリング（Domain）

- 各回答 → 特性スコア加算
- 悩みタグ付与
- 有料/無料許容度の算出

**責務:** 回答から数値・タグを生成。商品名を参照しない。

### Layer 3: タイプ判定（Domain）

- 特性スコア → 診断タイプ決定
- 複数軸からのタイプ名生成（例: 「自力予想×少点数セカンドオピニオン型」）

**責務:** スコアからタイプを決定。商品とは独立。

### Layer 4: 出口判定（Domain）

- タイプ + 悩みタグ + 許容度 → 出口カテゴリ決定
- 出口: `free_only` | `free_affiliate` | `paid_affiliate` | `own_product` | `nothing_now` | `future_consider`

**責務:** どの出口に送るかを決定。具体的な商品はまだ選ばない。

### Layer 5: 商品適合（Domain）

- 適合条件（タイプ + タグ + 出口）→ 商品マスター検索
- スコアリング: 適合度 × 優先度（ユーザー適合 > 信頼 > 継続 > 収益）

**責務:** 条件に合う候補を列挙。報酬額は優先度の一部要素に過ぎない。

### Layer 6: 表示生成（Application）

- 診断結果テキスト（本人の回答を引用）
- 漫画ID決定
- CTA段階決定
- 商品紹介文（向いている人/向かない人含む）

**責務:** 各レイヤーの出力を組み合わせてUI用データを生成。

### Layer 7: 計測（Infrastructure）

- 行動ログ記録
- A/Bテストバリアント管理

## マスターデータの関係

```
questions ──→ (回答) ──→ trait_scores
                              │
                              ↓
                         results ←── comics
                              │
                              ↓
                    exit_rules (出口判定)
                              │
                              ↓
                    products ←── content (無料)
                              │
                              ↓
                         display
```

### 結合ポイント（疎結合を保つ箇所）

| 結合 | 方式 | 理由 |
|------|------|------|
| 質問 → スコア | 質問マスター内のスコア定義 | 質問追加時に商品変更不要 |
| スコア → タイプ | タイプ判定ルール（閾値） | ルール変更で商品変更不要 |
| タイプ → 出口 | 出口ルールマスター | 出口追加が独立 |
| 出口+条件 → 商品 | 商品マスターの適合タグ | 商品入替えが独立 |
| タイプ → 漫画 | 漫画マスターの対象タイプ/悩み | 漫画追加が独立 |

## 出口判定ルール（exit_rules）

```typescript
interface ExitRule {
  exitType: ExitType;
  conditions: {
    traitRanges?: Partial<Record<TraitAxis, { min?: number; max?: number }>>;
    requiredTags?: string[];
    excludedTags?: string[];
    paidTolerance?: { min?: number; max?: number };
  };
  priority: number; // 複数マッチ時の優先度
}
```

**重要:** 1人のユーザーに複数出口候補が出る場合、最も適合度の高い1つを主出口とし、他は副次CTAとして提示可能。

## CTA段階設計

| 段階 | 関心度 | CTA例 | 遷移先 |
|------|--------|-------|--------|
| L1 | 弱 | 無料で続きを見る | 無料コンテンツ |
| L2 | 中 | このタイプの攻略法を見る | タイプ別記事 |
| L3 | 商品関心 | 自分に合う選択肢を見る | 出口別ページ |
| L4 | 強 | 有料サービスも含めて比較 | 比較ページ |
| L5 | 購買直前 | サービス詳細を見る | 商品詳細/ASP |

**Pull型:** L4/L5はユーザーが明示的に深掘りを選んだ場合のみ表示。

## 商品適合スコアリング

```
適合スコア = (
  特性マッチ度 × 0.4 +
  悩みタグマッチ度 × 0.3 +
  出口適合度 × 0.2 +
  収益要素 × 0.1  // 最優先ではない
)
```

収益要素は tie-breaker 程度。ユーザー適合が圧倒的に優先。

## 将来拡張ポイント

| 拡張 | 影響範囲 | 既存への影響 |
|------|---------|-------------|
| 商品追加 | products マスターのみ | なし |
| 質問追加 | questions マスターのみ | なし |
| 出口追加 | exit_rules 追加 | なし |
| 漫画追加 | comics マスターのみ | なし |
| A/Bテスト | 表示層 + 計測層 | ロジック層に影響なし |
| 新しい診断軸 | trait定義 + 質問スコア | 既存タイプ判定ルールの調整のみ |
